- 이 phase가 끝나면 반드시 커밋한다.
- 커밋 전에 동작 확인을 하고, 확인한 명령이나 수동 테스트를 기록한다.
- phase 종료 시 회귀 위험과 개선사항을 리뷰한다.
- 완료한 내용은 `completion-log.md`에 업데이트한다.
- 구현 중 배운 내용 때문에 남은 작업 순서나 범위가 달라지면 이후 phase 문서도 함께 업데이트한다.
- 계획과 실제 구현이 다르면 실제 구현을 기준으로 문서를 고친다.

## 목표

채널톡 Web SDK를 설치하고, 로그인 전/후 고객 식별 차이를 데모로 보여준다. 이 phase가 면접의 핵심이다.

## 구현 범위

- 채널톡 Web SDK 스크립트 추가
- 환경변수로 plugin key 또는 boot 설정값 관리
- 로그인하지 않은 방문자 boot 흐름
- 로그인한 회원의 `memberId`, 이름, 이메일, 가입일 전달
- 고객 속성 전달: 고객 등급, 피부 타입, 최근 본 상품, 장바구니 수량, 장바구니 합계
- `/debug/channel` 디버그 패널
- SDK에 넘기는 payload를 서버 또는 뷰에서 확인할 수 있게 정리

## 사용자 관점 설명

채널톡 버튼은 쇼핑몰 오른쪽 아래에 뜨는 상담入口다. 고객이 로그인하지 않았을 때는 이름표가 없는 방문자처럼 보이고, 로그인하면 쇼핑몰 회원 정보가 붙는다. 디버그 패널은 개발자가 그 이름표에 어떤 내용이 적혔는지 확인하는 화면이다.

## 기술 포인트

- 실제 채널톡 계정의 plugin key는 `.env` 또는 credentials로 관리한다.
- 민감한 값은 Git에 커밋하지 않는다.
- `memberId`는 바뀌면 안 된다. 이메일은 바뀔 수 있으므로 고객 식별 키로 쓰지 않는다.
- SDK 호출이 실패해도 쇼핑몰 화면 자체는 깨지지 않게 한다.
- 실제 Open API 호출은 구현 범위에서 제외한다. 필요하면 README에 다음 단계로 적는다.

## 검증 방법

- 채널톡 버튼이 화면에 보인다.
- 로그아웃 상태에서 앱이 깨지지 않는다.
- 로그인 후 SDK payload에 `memberId`, 이름, 이메일이 포함된다.
- `/debug/channel`에서 현재 고객 속성을 확인할 수 있다.
- 환경변수가 없을 때의 안내 또는 fallback이 동작한다.

## 완료 조건

- `Anonymous`에서 `Member`로 바뀌는 흐름을 실제 화면과 코드로 설명할 수 있다.
- 면접에서 “고객사 개발팀이 어떤 값을 먼저 받아야 하는지” 설명할 수 있다.
- SDK 문제 발생 시 어떤 값을 확인할지 디버그 패널로 보여줄 수 있다.
