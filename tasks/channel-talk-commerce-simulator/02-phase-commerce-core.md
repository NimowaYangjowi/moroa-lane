# Phase 2: Commerce Core

## 공통 진행 지시사항

- 이 phase가 끝나면 반드시 커밋한다.
- 커밋 전에 동작 확인을 하고, 확인한 명령이나 수동 테스트를 기록한다.
- phase 종료 시 회귀 위험과 개선사항을 리뷰한다.
- 완료한 내용은 `completion-log.md`에 업데이트한다.
- 구현 중 배운 내용 때문에 남은 작업 순서나 범위가 달라지면 이후 phase 문서도 함께 업데이트한다.
- 계획과 실제 구현이 다르면 실제 구현을 기준으로 문서를 고친다.

## 목표

고객이 상품을 둘러보고 특정 상품에서 상담을 시작할 수 있는 기본 커머스 화면을 만든다. 이 phase부터는 실제 사이트처럼 보이는 예제 사이트라는 인상을 주는 것이 중요하다.

## 구현 범위

- `Product` 모델 생성
- 상품 seed 데이터 작성
- 홈 화면의 추천 상품 영역
- 상품 목록 화면
- 상품 상세 화면
- 최근 본 상품 기록을 위한 `ProductView` 모델 또는 세션 기반 임시 기록

## 사용자 관점 설명

상품 목록은 고객이 여러 제품을 훑어보는 진열대다. 상품 상세는 고객이 “이 상품이 나에게 맞을까?”라고 질문하기 쉬운 화면이다. 채널톡 상담이 시작되는 실제 맥락을 만들기 위해 상품 상세 화면이 중요하다. 카드, 이미지, 가격, 설명, CTA가 갖춰져야 면접관이 실제 커머스 고객사 상황으로 받아들이기 쉽다.

## 기술 포인트

- 상품 데이터는 SQLite에 seed로 넣는다.
- 이미지는 외부 URL 또는 로컬 placeholder 중 하나로 시작한다.
- 상품 상세 진입 시 최근 본 상품을 기록한다.
- 로그인하지 않은 사용자의 최근 본 상품은 세션에 저장할지, 로그인 이후부터만 저장할지 구현 중 결정하고 문서에 반영한다.

## 검증 방법

- seed 실행 후 상품이 생성되는지 확인한다.
- 홈, 목록, 상세 화면이 열린다.
- 상품 상세에 가격, 카테고리, 설명이 표시된다.
- 최근 본 상품 기록 방식이 동작한다.

## 완료 조건

- 면접 데모에서 “고객이 어떤 상품을 보다가 문의했는지” 설명할 수 있다.
- 상품 관련 화면만으로도 실제 커머스 예제 사이트처럼 보인다.
- 다음 phase에서 회원 정보와 상품 조회 이력을 연결할 수 있다.
