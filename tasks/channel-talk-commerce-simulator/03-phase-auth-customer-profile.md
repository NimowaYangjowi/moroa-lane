# Phase 3: Auth And Customer Profile

## 공통 진행 지시사항

- 이 phase가 끝나면 반드시 커밋한다.
- 커밋 전에 동작 확인을 하고, 확인한 명령이나 수동 테스트를 기록한다.
- phase 종료 시 회귀 위험과 개선사항을 리뷰한다.
- 완료한 내용은 `completion-log.md`에 업데이트한다.
- 구현 중 배운 내용 때문에 남은 작업 순서나 범위가 달라지면 이후 phase 문서도 함께 업데이트한다.
- 계획과 실제 구현이 다르면 실제 구현을 기준으로 문서를 고친다.

## 목표

익명 방문자가 회원으로 전환되는 흐름을 만든다. 채널톡 설명에서는 이 phase가 `Anonymous`에서 `Member`로 넘어가는 핵심 근거가 된다.

## 구현 범위

- Rails 네이티브 방식의 회원가입
- 로그인
- 로그아웃
- `User` 모델
- 비밀번호 저장을 위한 `password_digest`
- 마이페이지
- 고객 속성 표시: 이름, 이메일, 가입일, 고객 등급, 피부 타입
- 로그인한 사용자의 최근 본 상품 표시

## 사용자 관점 설명

회원가입 화면은 쇼핑몰이 고객의 이름표를 만드는 곳이다. 로그인 전에는 같은 사람이 다시 와도 확실히 알아보기 어렵지만, 로그인 후에는 쇼핑몰의 회원 ID로 같은 고객임을 알아볼 수 있다.

## 기술 포인트

- Devise보다 Rails 기본 인증 흐름을 우선 검토한다.
- `users.id`를 그대로 외부에 노출할지, `memberId`용 문자열을 만들지 결정한다.
- 추천 기본값은 `"user_#{user.id}"` 형태의 안정적인 `memberId`다.
- 이메일 중복 검증과 비밀번호 최소 길이는 넣는다.

## 검증 방법

- 회원가입이 된다.
- 로그인과 로그아웃이 된다.
- 잘못된 비밀번호로 로그인할 수 없다.
- 마이페이지에서 고객 속성이 보인다.
- 로그인 사용자와 최근 본 상품이 연결된다.

## 완료 조건

- `Anonymous`와 `Member`의 차이를 실제 화면으로 설명할 수 있다.
- 채널톡에 넘길 고객 속성의 원천 데이터가 준비된다.
- 다음 phase에서 장바구니와 주문 이력을 사용자에게 연결할 수 있다.
