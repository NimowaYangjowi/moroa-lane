# Phase 6: Demo Polish

## 공통 진행 지시사항

- 이 phase가 끝나면 반드시 커밋한다.
- 커밋 전에 동작 확인을 하고, 확인한 명령이나 수동 테스트를 기록한다.
- phase 종료 시 회귀 위험과 개선사항을 리뷰한다.
- 완료한 내용은 `completion-log.md`에 업데이트한다.
- 구현 중 배운 내용 때문에 남은 작업 순서나 범위가 달라지면 이후 phase 문서도 함께 업데이트한다.
- 계획과 실제 구현이 다르면 실제 구현을 기준으로 문서를 고친다.

## 목표

면접에서 5분 안에 보여줄 수 있는 데모 흐름과 설명 자료를 완성한다. 프로젝트 `README.md`도 이 phase에서 최종 정리한다.

## 구현 범위

- 기본 UI 정리
- 모바일/데스크톱에서 주요 화면 깨짐 확인
- README 완성
- 데모 계정과 seed 데이터 정리
- 면접용 데모 스크립트 작성
- 회귀 위험 최종 점검
- 남은 개선사항 목록 작성

## 사용자 관점 설명

이 phase는 기능을 더 많이 넣는 단계가 아니다. 면접관이 봤을 때 “작은 커머스 서비스에서 채널톡 연동 흐름을 잘 이해하고 있구나”라고 느낄 수 있게 화면과 설명을 정리하는 단계다.

## README에 포함할 내용

- 프로젝트 목적: 채널톡 기술면접용 시뮬레이션
- 기술 스택
- 설치 및 실행 방법
- seed 데이터 생성 방법
- 데모 계정
- 데모 시나리오
- 채널톡 SDK 설정 방법
- `Anonymous`, `Lead`, `Member` 설명
- `memberId`를 안정적인 고객 식별 키로 쓰는 이유
- 구현하지 않은 범위
- 다음 단계로 확장 가능한 항목

## 검증 방법

- README만 보고 로컬 실행이 가능하다.
- 홈, 상품 목록, 상품 상세, 회원가입, 로그인, 마이페이지, 장바구니, 디버그 패널을 순서대로 확인한다.
- 채널톡 SDK 설정값이 없을 때도 앱 설명을 따라갈 수 있다.
- 전체 데모를 5분 안에 말로 설명할 수 있다.

## 완료 조건

- 면접 전날 다시 열어도 바로 데모할 수 있다.
- README가 프로젝트의 의도와 실행 방법을 충분히 설명한다.
- 남은 위험과 개선사항이 `completion-log.md`에 정리되어 있다.
- 최종 커밋이 완료되어 있다.
