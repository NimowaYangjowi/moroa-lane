- 계획과 실제 구현이 다르면 실제 구현을 기준으로 문서를 고친다.

## 목표

고객의 구매 의도와 과거 구매 맥락을 보여주는 장바구니와 가짜 주문 이력을 만든다. 실제 결제는 구현하지 않는다.

## 구현 범위

- `CartItem` 모델
- 상품 상세에서 장바구니 담기
- 장바구니 화면
- 수량 변경
- 장바구니 상품 삭제
- `Order`, `OrderItem` 모델
- seed로 가짜 주문 이력 생성
- 마이페이지에 최근 주문 표시

## 사용자 관점 설명

장바구니는 고객이 살까 말까 고민하는 물건 목록이다. 상담원이 이 정보를 보면 “지금 고객이 어떤 상품을 고민 중인지” 빠르게 알 수 있다. 주문 이력은 고객이 예전에 무엇을 샀는지 보여주기 때문에 교환, 반품, 재구매 상담에 도움이 된다.

## 기술 포인트

- 결제 버튼은 만들더라도 실제 결제는 연결하지 않는다.
- 주문 생성 기능은 seed 중심으로 둔다.
- 장바구니 합계 금액은 채널톡 고객 속성으로 넘길 수 있게 계산 메서드를 둔다.
- 주문 상태는 `paid`, `shipped`, `delivered` 같은 더미 상태로 충분하다.

## 검증 방법

- 로그인한 사용자가 상품을 장바구니에 담을 수 있다.
- 장바구니 수량 변경과 삭제가 된다.
- 마이페이지에서 가짜 주문 이력이 보인다.
- 장바구니 합계와 주문 총액이 맞다.

## 완료 조건

- 상담 맥락으로 넘길 `cart_items_count`, `cart_total`, `last_order_at` 같은 값의 원천이 생긴다.
- “고객이 어떤 구매 상태에서 문의하는지” 면접에서 설명할 수 있다.
- 결제가 없다는 점이 README와 데모 설명에 명확히 적혀 있다.
